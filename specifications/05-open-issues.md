# 05 - Open issues and dispositions

Single list of the bugs, inconsistencies, risks and product questions found in the 1.5 code. It replaces the four separate lists that used to end files 01-04 (old numbers are kept in the "Formerly" column so older notes still resolve). Citation prefixes: see the [README](README.md#source-baseline-and-citation-prefixes).

## Dispositions

Each item has one disposition. It tells a reimplementer what to do.

| Disposition | Meaning for a reimplementation |
|---|---|
| **keep** | Wire or disk compatibility depends on it. Reproduce it exactly, even if it looks odd. |
| **fix** | A bug. Do not reproduce it. The "Recommendation" column gives the intended behaviour; it never changes what goes on the wire or on disk. |
| **decide** | A product or security choice. The 1.5 behaviour is given; the product owner must confirm or change it. Until then, the recommendation applies. |
| **info** | Repository hygiene or build detail of the Python app. No effect on a reimplementation. |

Severity: **high** (data loss, security, or a feature that cannot work), **medium** (wrong behaviour a user will hit), **low** (cosmetic or rare).
