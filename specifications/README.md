# Witness Angel Authenticator — Specification

Specification of the Witness Angel Authenticator application (v1.5), detailed enough to
reimplement it in another language or framework while staying interoperable with existing
authenticator folders, the Witness Angel gateway, and `wacryptolib`.

## Normative language

| Tag | Meaning |
|---|---|
| **MUST** / **MUST NOT** | Required for interoperability (disk, wire, existing keys) or for a security property. A reimplementation that breaks it is wrong. |
| **SHOULD** | Recommended; deviate only for a stated reason. |
| **MAY** | Optional; either choice interoperates. |
| **INFO** | Description of the 1.5 behaviour, for reference. It is not a requirement. |

Rules:

- [04 §0](04-data-and-protocols.md#0-normative-interop-requirements-checklist) collects every MUST about bytes on disk and on the wire. [01 Part A](01-architecture-and-platform.md#part-a---requirements-a-reimplementation-must-keep) collects the platform requirements.
- Elsewhere, untagged text describes the 1.5 behaviour, which is the reference for the user experience **except** where [05](05-open-issues.md) gives the item the disposition *fix* or *decide*. Bugs are never requirements.
- Behaviours that exist only as Python `assert`s are absent from release builds (asserts are stripped: [05 OI-40](05-open-issues.md#e-data-formats-and-crypto)). They are marked "debug builds only".

## Glossary

| Term | Meaning | Defined in |
|---|---|---|
| **Authenticator** | A keystore (folder with metadata + keypairs) held by a *key guardian*; its private keys are protected by the guardian's passphrase. Also the name of this app. | [03 §1](03-business-logic.md#1-domain-concepts), [04 §2](04-data-and-protocols.md#2-on-disk-layout-of-an-authenticator) |
| **Authdevice** | A removable drive (USB key) holding an authenticator folder at its root. | [01 §4](01-architecture-and-platform.md#4-storage-locations-exact-per-os) |
| **Key guardian** (trustee) | Person owning an authenticator, who accepts or rejects revelation requests. In the cryptolib, an authenticator used by a recorder is a *trustee* of type `authenticator`. | [03 §1](03-business-logic.md#1-domain-concepts) |
| **TrusteeApi** | Cryptolib class performing the guardian-side operations (here: decrypt a ciphertext with a private key, trying the given passphrases). | [03 §7.3](03-business-logic.md#73-accept-the-decryption-algorithm) |
| **Keystore** | Storage of asymmetric keypairs indexed by `(keychain_uid, key_algo)`. | [04 §2](04-data-and-protocols.md#2-on-disk-layout-of-an-authenticator) |
| **keystore_uid** vs **keychain_uid** | `keystore_uid` identifies the whole authenticator (the "Authenticator ID" given to users). `keychain_uid` identifies one keypair inside it. Both are uuid0 values. | [04 §2.2](04-data-and-protocols.md#22-keystore_metadatajson-schema) |
| **uuid0** | 16-byte UUID made of a 6-byte timestamp and 10 random bytes, with no RFC version bits. | [04 §1](04-data-and-protocols.md#1-primitive-encodings-used-everywhere) |
| **Keystore secret** | Random token in the authenticator metadata; bearer credential of the guardian at the gateway. | [03 §1](03-business-logic.md#1-domain-concepts) |
| **Keyfactory** | A keystore type (`keystore_type = "keyfactory"`) used by recorders and claimants for their own keys, for example the claimant's one-time response key. Not created by this app. | [04 §2.2](04-data-and-protocols.md#22-keystore_metadatajson-schema) |
| **Cryptainer** | Encrypted container produced by Witness Angel recorders; its symmetric keys are encrypted with authenticators' public keys. | [03 §1](03-business-logic.md#1-domain-concepts) |
| **Symkey** | Symmetric key (AES or ChaCha20 key dict) protecting a cryptainer payload. | [04 §5.1](04-data-and-protocols.md#51-symmetric-ciphers-context-only) |
| **Shamir shard** | One share of a secret split with Shamir's scheme; a cryptainer may require several guardians' shards to rebuild a symkey. Opaque to this app. | [04 §5.1](04-data-and-protocols.md#51-symmetric-ciphers-context-only) |
| **key_struct_bytes** | The plaintext recovered by the guardian for one symkey decryption request: Extended-JSON bytes of a symkey, a shard or an inner ciphertext. Opaque to this app. | [03 §7.3](03-business-logic.md#73-accept-the-decryption-algorithm) |
| **Cipherdict** | Dict produced by an encryption; for RSA-OAEP it is `{"ciphertext_chunks": [bytes, …]}`. | [04 §5.2](04-data-and-protocols.md#52-rsa-oaep-chunked-encryption-the-format-the-authenticator-decrypts-and-produces) |
| **Extended JSON** (extjson) | JSON with typed wrappers (`$binary`, `$date`, `$numberInt`…) for bytes, UUIDs, dates and integers. **Canonical** mode wraps every typed value; **relaxed** mode uses shorter forms (`$uuid`, ISO dates, plain ints). | [04 §3](04-data-and-protocols.md#3-serialization-extended-json-extjson) |
| **Claimant / requestor** | Party wanting to decrypt cryptainers; sends a *revelation request* via the gateway. | [03 §1](03-business-logic.md#1-domain-concepts) |
| **Revelation station** | A claimant application that holds cryptainers and asks guardians, through the gateway, to reveal their keys. Not part of this app. | [03 §1](03-business-logic.md#1-domain-concepts) |
| **Revelation request** | Request, relayed by the gateway, asking the guardian to decrypt one or more symmetric keys and re-encrypt them for the requestor. **The UI calls it an "authorization request"** ("Demande d'autorisation"); the "Authorizations" button opens the list. | [03 §7](03-business-logic.md#7-revelation-request-processing) |
| **Symkey decryption request** | One item of a revelation request: one ciphertext to decrypt with one authenticator key, plus cryptainer info. | [04 §7.3.3](04-data-and-protocols.md#733-list_authenticator_revelation_requests) |
| **Gateway** | Witness Angel web registry (JSON-RPC) where authenticators are published and revelation requests exchanged. Default URL: `https://api.witnessangel.com/gateway/jsonrpc/`. | [04 §7](04-data-and-protocols.md#7-gateway-json-rpc-protocol) |
| **Publication** | One-time upload of an authenticator's public metadata and public keys to the gateway. | [03 §6](03-business-logic.md#6-publication-to-the-gateway) |
| **Flightbox** | The cryptolib command-line tool (`flightbox authenticator create/check/delete…`); its behaviour is cited where it differs from the GUI. | [03 §4.4](03-business-logic.md#44-atomicity-and-failure-behaviour) |
